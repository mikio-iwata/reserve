# _reserve2 インシデントレポート 2026-06-15

## 結論
- `_reserve2` の表示テスト結果は、そのまま納品判定に使用できない。
- 原因は、`reserve.asp` のレスポンシブ切替境界（特に `640px〜750px台`）を十分に通しておらず、表示崩れを見落としたこと。
- よって、`index.asp / main.asp / reserve.asp` の表示確認は、既存結果をいったん「参考」に格下げし、境界幅を含めて再試験する。

## なぜこれを最優先で扱うか
- 今回の不備は単なる1画面の見落としではなく、テスト設計そのものの不足である。
- 納品物に対して「375px と 1280px が通った」だけでは不十分で、実装上の切替点を跨ぐ幅での確認が必須だった。
- この状態で「合格」と扱うと、客先提出後に同系統の崩れが再発しても防げない。

## インシデント概要
- `reserve.asp` にて、画面幅が `900px未満` の一部領域で表示が不自然になり、`750px以下` でレイアウト崩れが発生した。
- 既存テストでは `375px / 1280px` の確認は実施していたが、実装上の切替点である `750px` 周辺を連続的に潰していなかった。
- その結果、レスポンシブ切替CSSの不整合を検出できなかった。

## 直接原因
- `work/_reserve2/etc/style.css` において、予約一覧の `schedule-table` を `@media (max-width: 750px)` でカード表示へ切り替えていた。
- 実際にはその切替が早すぎ、中間幅で一覧の構造が破綻した。

## 根本原因
- 表示テストの設計不足。
- 具体的には、以下の観点が欠けていた。
  - 切替境界幅の確認
  - 代表幅だけでなく、連続幅での再現確認
  - `reserve.asp` のように一覧構造が切り替わる画面の重点確認
