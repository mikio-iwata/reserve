## 1. 接続方法（人間が用意 → Codexが接続）

### 人間側（テスト開始前に実施済みであること）
1. 専用プロファイルで Chrome をリモートデバッグ起動する:
   chrome.exe --remote-debugging-port=9222 --user-data-dir="C:\codex_chrome_profile"
2. その Chrome で **テスト用アカウント**でログインし、予約システムの index.asp を開いておく。
3. このウィンドウ／タブは閉じない。セッションを維持する。

### Codex側
- http://localhost:9222 に CDP 接続し、**既存のログイン済みタブを再利用**する
  （Playwright なら connectOverCDP、puppeteer なら connect で既存 page を取得）。
- 新規にログインし直さない。人間が用意したセッションをそのまま使う。
- ※ 接続に MCP/プラグインが必要なら、必要なものを申告すること（人間が導入する）。

## 2. 厳守ルール（前回までの教訓）
- 実行できない項目を「合格」にしない。未実施は未実施のまま残す。
- 「ソース確認のみ」は "参考"。"合格" と書かない。
- セッションが切れたら（ログイン画面/エラーに飛んだら）作業を止め、
  「再ログインが必要」と報告する。勝手に資格情報を入力しない。
- 予約/キャンセルは **テスト用アカウント限定**。本番生徒データを操作しない。
- DB不足で再現できないケースは捏造せず「データ不足で未実施」と記録する。

## 3. 画面遷移は正規フローを守る
- main.asp / reserve.asp は index.asp 経由でセッション
  (ThisCourse / ThisCourseName / ThisCourseType / ThisNoRsvtime / CourseNumber) が
  セットされて初めて正しく動く。
- **deep-link で main/reserve を直接開かない**。必ず
  index.asp（コース選択）→ main.asp（予約・キャンセル）→ reserve.asp（クラス選択）
  の順に画面遷移して状態を作ること。
- index.asp は冒頭でコース系セッションをクリアするため、main で確認したい時は
  毎回 index からコースを選び直すこと。

## 4. 作業A: A_表示・レスポンシブ（Win Chrome/Edge/Firefox 約111件）
対象画面: index.asp / main.asp / reserve.asp（error.asp は実施済み）

各画面 × 各ブラウザ(Win Chrome/Edge/Firefox) × 各幅で表示を確認する。
- 幅: 320 / 375 / 768 / 900 / 1024 / 1280 / 1366 / 1920 px
- 確認ポイント:
  - 横スクロール(overflow)が出ない（scrollWidth <= innerWidth）
  - ヘッダー画像がコンテナを超えない（特に 751〜900px帯, BUG-003修正の最終確認）
  - ボタン/表/カレンダー/予約一覧が画面外にはみ出さない、重ならない
  - タップ領域 >= 44x44px
- 証跡: 各 ID で 375px / 1280px のスクリーンショット必須。
  数値根拠(scrollWidth, innerWidth, 画像矩形)も取得して JSON 等に残す。
- Edge/Firefox は実ブラウザで確認する（Chromiumエミュレーションで代替合格にしない）。

※ Firefox の数値測定(A-144/A-147)に geckodriver/Selenium/Playwright が要る場合は申告すること。
