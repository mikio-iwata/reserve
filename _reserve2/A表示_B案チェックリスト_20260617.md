# A_表示・レスポンシブ 合格ライン（B案）チェックリスト

作成日: 2026-06-17 / 作成: レビュー担当
目的: 発注側の明示基準が無いため、本書を「レスポンシブ対応 完了の合格ライン」として運用する。
対象画面: index.asp(コース選択) / main.asp(予約・キャンセル) / reserve.asp(クラス選択) / error.asp(エラー)

---

## 0. 合格ラインの考え方（B案）
- 「全幅 × 全観点 × 全ブラウザ」の網羅は求めない。
- 利用者が実際に困る項目（はみ出し・押せない・崩れる）を主要幅で確実に押さえる。
- アクセシビリティ系(ズーム/alt等)は代表ブラウザ1つで確認すれば可とする。
- 実機でしか確認できないもの(iOS/Android/Mac Safari)は人間が代表パスのみ実施。

判定の合格条件（各観点共通）:
- 横スクロールが出ない（scrollWidth <= innerWidth）
- ヘッダー画像がヘッダー枠を超えない（headerOverflow = false）
- ボタン/表/カレンダー/フォームが画面外に出ない・重ならない
- 文字が読める（つぶれ・重なり無し）

---

## 1. 幅の定義
- コア幅（必須）: **375 / 768 / 1280**
- エッジ幅（はみ出し確認のみ）: **320 / 900 / 1920**
  - 900 は BUG-003(751〜900px帯のヘッダー)再発防止のため必須に含める
- 回転確認: 375x667 ⇄ 667x375

## 2. ブラウザの定義
- 自動化可（CODEX, CDP/Playwright）: **Win Chrome / Win Edge / Win Firefox**
- 実機のみ（人間）: **iOS Safari / Android Chrome / iPad Safari / macOS Safari**

## 3. CODEX 担当（Win Chrome / Edge / Firefox 自動）

### 3-1. 必須観点 × コア幅(375/768/1280) × 3ブラウザ
各画面(index/main/reserve)で以下を確認・証跡(数値JSON＋スクショ):
- [ ] 横スクロール発生なし
- [ ] ヘッダ画像の追従（枠超えなし）
- [ ] パンくずの折返し
- [ ] ボタン配置(action-row)
- [ ] テーブルのレスポンシブ化（main=レッスン一覧 / reserve=スケジュール表）
- [ ] カレンダー表示（reserve のみ）
- [ ] フォーム入力域 select（main のみ）

### 3-2. はみ出し確認のみ × エッジ幅(320/900/1920) × 3ブラウザ
各画面で以下のみ:
- [ ] 横スクロール発生なし
- [ ] ヘッダ画像の追従（特に 900px）

### 3-3. タップターゲット × 375 × 3ブラウザ
- [ ] 主要ボタン/ラジオ/リンクが 44x44px 以上（数値で記録）

### 3-4. アクセシビリティ/特殊条件（代表= Win Chrome のみ, 375）
- [ ] ブラウザズーム200%（文字が読める/重ならない）
- [ ] 画像欠落時(alt)（alt文字が出る）
- [ ] 文字エンコード（Shift_JIS で文字化けなし。各画面1回）
- [ ] 縦/横画面切替（375x667 ⇄ 667x375 で崩れない）
- [ ] 長文・端値表示（長いコース名/メッセージで折返し・はみ出し無し）

※ Firefox はツールが無ければ数値の代わりにスクショ視覚確認で可。その旨を明記。
※ 実行できない項目は捏造せず「未実施(理由)」で残す。

## 4. 人間 担当（実機・代表パスのみ）
各実機で 4画面(index/main/reserve/error) を**その端末の標準幅**で開き、目視確認:
- [ ] iOS Safari: 横スクロール無し / ヘッダー枠内 / ボタン押せる / 文字読める
- [ ] Android Chrome: 同上
- [ ] iPad Safari: 同上
- [ ] macOS Safari: 同上（デスクトップ幅で崩れ無し）

※ error.asp はログイン不要。index/main/reserve はログイン後に正規フロー(index→コース→main→学校→reserve)で開く。
※ 1画面でも崩れがあれば不具合として記録（スクショ添付）。

---

## 5. このラインで「対象外」にしてよいもの
- 上記に含めない細かな幅(360/414/1024/1366)の全観点総当たり
- 実機4種 × 全観点 × 全幅の網羅
→ これらは B案では「対象外（合格ライン外）」とし、Excelの該当行は対象外で確定してよい。
